# 学习任务(7) — ROS2 Jazzy 图像通信与组件化 详解

## 一、任务总体定位

这个任务是在**学习任务6（ROS2基础通信与自定义接口）**的进阶。之前你学会了字符串消息的发布/订阅，现在要把通信内容**从简单字符串升级为图像**，并进一步学习 **ROS 2 Component（组件）** 机制。

核心关键词：
- `ROS 2 Component` / `rclcpp_components`
- `sensor_msgs/Image`
- `cv_bridge`
- `OpenCV`
- `RViz2`
- `进程内通信（intra-process comms）`

## 二、第一部分：图像发布与订阅

### 2.1 图像发布节点

**要求：**
- 用 OpenCV 创建一幅 **1920×1080** 的图像
- 在图像中央绘制文字 `Hello, ROS 2 Jazzy: N`，其中 N 随发送次数递增
- 发布频率 **10 Hz**
- 话题名：`/camera/image`

**关键技术点：**

#### ① 用 OpenCV 创建图像

```cpp
cv::Mat image = cv::Mat::zeros(1080, 1920, CV_8UC3);  // 1080行×1920列，3通道8位无符号
```

- `CV_8UC3` = 8-bit Unsigned, 3 Channel（即 BGR 彩色图）
- 注意 OpenCV 是 `(rows, cols)` = `(height, width)` 的顺序

#### ② 在图像上绘制文字

```cpp
std::string text = "Hello, ROS 2 Jazzy: " + std::count;
int fontFace = cv::FONT_HERSHEY_SIMPLEX;
double fontScale = 2.0;
int thickness = 3;
cv::putText(image, text, cv::Point(100, 540), fontFace, fontScale, cv::Scalar(255, 255, 255), thickness);
```

#### ③ 将 `cv::Mat` 转为 `sensor_msgs/msg/Image`

这是**核心难点**。`cv::Mat` 是 OpenCV 的图像类型，ROS 2 不认识它，必须用 `cv_bridge` 转换：

```cpp
#include <cv_bridge/cv_bridge.h>

// 方法一：用 toCvCopy 的逆操作
sensor_msgs::msg::Image::SharedPtr msg = cv_bridge::CvImage(
    std_msgs::msg::Header(), "bgr8", image).toImageMsg();
```

- `cv_bridge::CvImage` 是一个桥梁类，把 ROS Header + 编码字符串 + cv::Mat 打包
- `"bgr8"` 表示编码方式（BGR 三通道 8bit）
- `.toImageMsg()` 输出 `sensor_msgs::msg::Image` 类型的消息

#### ④ 正确填写消息字段

```cpp
msg->header.stamp = this->now();           // 时间戳
msg->header.frame_id = "camera_frame";     // 坐标系ID
msg->encoding = "bgr8";                    // 图像编码
msg->height = image.rows;                  // 图像高度
msg->width = image.cols;                   // 图像宽度
msg->step = image.step;                    // 每行字节数
msg->data.assign(image.data, image.data + image.total() * image.elemSize());
```

> 实际上如果用 `cv_bridge` 的 `toImageMsg()`，这些字段会自动填好，但理解每个字段的含义很重要。

#### ⑤ 发布频率控制

```cpp
// 在构造函数中创建定时器
timer_ = this->create_wall_timer(
    std::chrono::milliseconds(100),  // 100ms = 10Hz
    std::bind(&ImagePublisher::timer_callback, this));
```

### 2.2 图像订阅节点

**要求：**
- 订阅 `/camera/image`
- 用 `cv_bridge` 转回 `cv::Mat`
- 用 OpenCV 窗口显示

**关键技术点：**

#### ① 订阅回调函数

```cpp
void image_callback(const sensor_msgs::msg::Image::SharedPtr msg) {
    try {
        cv::Mat frame = cv_bridge::toCvCopy(msg, "bgr8")->image;
        cv::imshow("Camera View", frame);
        cv::waitKey(1);
    } catch (cv_bridge::Exception& e) {
        RCLCPP_ERROR(this->get_logger(), "cv_bridge exception: %s", e.what());
    }
}
```

#### ② `cv_bridge` 的两种转换方式

| 方法 | 说明 |
|------|------|
| `toCvCopy(msg, encoding)` | **深拷贝**，返回 `CvImage::ConstPtr`，安全但慢 |
| `toCvShare(msg, encoding)` | **浅拷贝**，共享数据，快但原消息不能被修改 |

对于图像这种大数据，`toCvShare` 更高效，但要注意线程安全。

## 三、第二部分：使用 RViz2 查看图像

### 3.1 操作步骤

1. 启动 RViz2：
   ```bash
   ros2 run rviz2 rviz2
   ```

2. 在左侧 **Displays** 面板点击 **Add**
3. 选择 **Image** 类型
4. 在 Image Display 的 **Topic** 中选择 `/camera/image`
5. 确认能看到与 OpenCV 窗口一致的画面

### 3.2 如果没有图像的排查思路

| 检查项 | 命令 | 判断 |
|--------|------|------|
| 话题是否存在 | `ros2 topic list` | 没有 → 发布节点没跑 |
| 是否有发布者 | `ros2 topic info /camera/image` | Publisher count = 0 → 发布节点没跑 |
| 是否持续发布 | `ros2 topic hz /camera/image` | 没有输出 → 发布频率为0或节点崩溃 |

> 本任务不要求深入分析 TF、复杂 QoS 或 RViz2 高级配置，重点是**把图像通信链路跑通**。

## 四、第三部分：ROS 2 Component（组件）

这是本任务的**重点和难点**。

### 4.1 什么是 Component？

**普通节点 vs 组件：**

| 对比项 | 普通可执行节点 | Component（组件） |
|--------|---------------|------------------|
| 运行方式 | 独立进程 `ros2 run pkg node` | 被加载到容器进程中 |
| 通信方式 | 进程间通信（DDS/共享内存） | 可进程内通信（零拷贝） |
| 资源占用 | 每个节点独立进程，开销大 | 共享一个进程，开销小 |
| 灵活性 | 固定 | 可动态加载/卸载 |
| 代码组织 | 继承 `rclcpp::Node` | 继承 `rclcpp_components::NodeInterface` |

### 4.2 创建组件

#### ① ImagePublisherComponent

```cpp
#include <rclcpp_components/register_node_macro.hpp>

class ImagePublisherComponent : public rclcpp::Node {
public:
    ImagePublisherComponent(const rclcpp::NodeOptions& options)
        : rclcpp::Node("image_publisher_component", options) {
        // 创建发布者、定时器...
    }
private:
    void timer_callback() {
        // 生成图像并发布...
    }
    rclcpp::Publisher<sensor_msgs::msg::Image>::SharedPtr publisher_;
    rclcpp::TimerBase::SharedPtr timer_;
    int count_ = 0;
};

// 注册组件（必须）
RCLCPP_COMPONENTS_REGISTER_NODE(ImagePublisherComponent)
```

#### ② ImageSubscriberComponent

```cpp
class ImageSubscriberComponent : public rclcpp::Node {
public:
    ImageSubscriberComponent(const rclcpp::NodeOptions& options)
        : rclcpp::Node("image_subscriber_component", options) {
        // 创建订阅者...
    }
private:
    void image_callback(const sensor_msgs::msg::Image::SharedPtr msg) {
        // 转换并显示...
    }
    rclcpp::Subscription<sensor_msgs::msg::Image>::SharedPtr subscription_;
};

RCLCPP_COMPONENTS_REGISTER_NODE(ImageSubscriberComponent)
```

### 4.3 CMakeLists.txt 中的关键配置

```cmake
# 将组件编译为共享库（不是可执行文件）
add_library(image_publisher_component SHARED
    src/image_publisher_component.cpp)
ament_target_dependencies(image_publisher_component
    rclcpp rclcpp_components sensor_msgs cv_bridge)

add_library(image_subscriber_component SHARED
    src/image_subscriber_component.cpp)
ament_target_dependencies(image_subscriber_component
    rclcpp rclcpp_components sensor_msgs cv_bridge)

# 注册组件
rclcpp_components_register_nodes(image_publisher_component
    "ImagePublisherComponent")
rclcpp_components_register_nodes(image_subscriber_component
    "ImageSubscriberComponent")

# 安装
install(TARGETS
    image_publisher_component
    image_subscriber_component
    ARCHIVE DESTINATION lib
    LIBRARY DESTINATION lib
    RUNTIME DESTINATION bin)
```

### 4.5 Launch 文件：将两个组件装入同一个容器

```python
from launch import LaunchDescription
from launch_ros.actions import ComposableNodeContainer
from launch_ros.descriptions import ComposableNode

def generate_launch_description():
    container = ComposableNodeContainer(
        name='my_container',
        namespace='',
        package='rclcpp_components',
        executable='component_container_mt',  # 多线程容器
        composable_node_descriptions=[
            ComposableNode(
                package='your_package',
                plugin='ImagePublisherComponent',
                name='image_publisher',
                extra_arguments=[{'use_intra_process_comms': True}]  # 开启进程内通信
            ),
            ComposableNode(
                package='your_package',
                plugin='ImageSubscriberComponent',
                name='image_subscriber',
                extra_arguments=[{'use_intra_process_comms': True}]
            ),
        ],
        output='screen',
    )
    return LaunchDescription([container])
```

**关键点：**
- `component_container_mt`：多线程组件容器（mt = multi-threaded）
- `use_intra_process_comms: True`：开启进程内通信，避免大数据的序列化/反序列化开销

### 4.6 "两个普通节点" vs "两个组件装入同一容器"的区别

| 方面 | 两个普通节点 | 两个组件装入同一容器 |
|------|-------------|-------------------|
| 进程数 | 2个独立进程 | 1个进程 |
| 通信机制 | DDS 进程间通信 | 可进程内通信（指针传递） |
| 数据拷贝 | 至少2次序列化+2次反序列化 | 零拷贝（直接传指针） |
| 延迟 | 较高 | 较低 |
| CPU/内存 | 较高 | 较低 |

## 五、第四部分：简单对比与思考（README 中回答）

### 问题1：`cv::Mat` 为什么不能直接作为 ROS 2 Topic 的消息类型发送？`cv_bridge` 在这里起什么作用？

**答：**
- ROS 2 的通信中间件（DDS）只能序列化**已知的消息类型**（由 `.msg` 文件定义）
- `cv::Mat` 是 OpenCV 的 C++ 类，包含指针、动态内存等，DDS 无法直接序列化
- `cv_bridge` 的作用：
  1. 将 `cv::Mat` 的像素数据提取出来，填入 `sensor_msgs/msg/Image` 的 `data` 数组
  2. 自动设置 `encoding`、`width`、`height`、`step` 等字段
  3. 提供编码转换（如 `bgr8` ↔ `rgb8`）

### 问题2：`sensor_msgs/msg/Image` 中的 `encoding`、`width`、`height` 分别表示什么？

| 字段 | 含义 | 示例 |
|------|------|------|
| `encoding` | 像素编码格式 | `"bgr8"`, `"rgb8"`, `"mono8"`, `"32FC1"` 等 |
| `width` | 图像宽度（列数） | 1920 |
| `height` | 图像高度（行数） | 1080 |

常见编码：
- `bgr8`：3通道，每通道8位，BGR顺序（OpenCV默认）
- `rgb8`：3通道，每通道8位，RGB顺序
- `mono8`：单通道灰度图
- `32FC1`：单通道32位浮点

### 问题3：ROS 2 Component 和普通可执行节点的主要区别是什么？

| 区别 | 普通节点 | Component |
|------|---------|-----------|
| 本质 | 独立可执行文件 | 共享库（.so） |
| 运行方式 | `ros2 run` 启动独立进程 | 被 `component_container` 加载 |
| 通信 | 必须走 DDS 进程间通信 | 可选择进程内通信（零拷贝） |
| 资源 | 每个节点一个进程 | 多个组件共享一个进程 |
| 动态性 | 启动时确定 | 可运行时动态加载/卸载 |

### 问题4：为什么图像这种数据量较大的消息适合了解进程内通信？

**答：**
- 图像数据量大（1920×1080×3 ≈ 6MB/帧），序列化/反序列化开销显著
- 进程间通信需要：序列化 → 网络传输/共享内存 → 反序列化，至少2次拷贝
- 进程内通信：直接传递指针，**零拷贝**，极大降低延迟和 CPU 占用
- 对于 10Hz 的高频图像，这个优化效果非常明显
